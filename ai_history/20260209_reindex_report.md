## 2. Thinking Process

### 문제 분석
- 불릿 기호(○□❍❏ 등)가 48.1% 청크에 포함 → 임베딩 공간 낭비
- Bold markdown(`**text**`) 6.2% → 의미 없는 포맷팅 토큰
- Heading markdown (`# text`) → 86개 청크
- 짧은 노이즈 청크(50-79자) 46개 → 검색 품질 저하
- PDF 파서가 불릿 기호를 backtick으로 감싸는 경우 발견 (`` `❏` ``)

### 설계 결정
1. **불릿 기호**: 라인 시작 불릿만 `- `로 변환 (인라인 ○○○는 의미 있는 플레이스홀더이므로 보존)
2. **Backtick 불릿**: PDF 파서 아티팩트 `` `❏` `` → `- ` 변환 추가
3. **테이블 보호**: PDF 마크다운 테이블(`|...|`, `|---|`)은 절대 건드리지 않음
4. **_MIN_CHUNK_LENGTH**: 50 → 80으로 상향 (50-79자 노이즈 청크 제거)
5. **수평선 제거**: HWP only (PDF는 테이블 구분선 보존)

### 수정 파일

| 파일 | 작업 | 내용 |
|------|------|------|
| `src/parsers/text_cleaner.py` | **신규** | 클리닝 모듈 (6 regex rules + backtick bullet) |
| `src/parsers/chunker.py` | **수정** | `_MIN_CHUNK_LENGTH` 50 → 80 |
| `scripts/ingest.py` | **수정** | `clean_documents()` 삽입 (parse → clean → chunk) |
| `scripts/audit_db.py` | **신규** | DB 품질 감사 스크립트 |

### 청크 수 증가 설명
총 청크 수가 9,343 → 9,562로 +219 증가한 이유:
- 클리닝으로 불릿/markdown이 제거되면서 텍스트가 짧아짐
- 짧아진 텍스트가 청커의 chunk_size(1000자) 경계에서 다르게 분할됨
- 일부 기존 단일 청크가 분할되어 수량 증가

### 잔존 불릿 분석 (723개, 7.6%)
- **인라인 불릿** (709개): `○○○부서`, `○○○ 사업` 등 의미 있는 플레이스홀더 → 의도적 보존
- **라인시작 잔존** (14개, 0.15%): 청킹 후 새 경계에서 발생한 edge case → 무시 가능
