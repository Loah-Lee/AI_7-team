# Preprocessor Pipeline v2.1.3  
## Known Limitations & Architectural Transition Plan

---

## 1. Executive Summary

Preprocessor Pipeline v2.1.3은 99개 전체 문서에 대해 Strict Contract 기반의 데이터 무결성과 실행 안정성을 확보하였다.  
Dense/Sparse 인덱스 정합성, `doc_id` 계약 준수, 행 수 일치 등 기술적 관점에서는 완전한 성공을 달성하였다.

그러나, 일부 특수 문서에서 의미론적 구조 파싱 품질 저하가 확인되었으며, 이는 시스템 설계의 범위와 통계 기반 접근 방식의 구조적 한계에서 기인한다.

본 문서는 해당 제약을 정의하고, 차기 버전(v3.0)을 위한 아키텍처 전환 방향을 제시한다.

---

## 2. Technical Integrity vs Semantic Fidelity

### 2.1 Technical Integrity (99/99 Pass)
- 모든 문서가 `doc_id` Strict Contract 준수
- Dense/Sparse row count 완전 일치
- 페이지 추적 정상 동작
- 예외 및 런타임 오류 없음

### 2.2 Semantic Fidelity Limitation
일부 문서에서 제목(Header)이 본문(Body)에 포함되어
논리적 계층 구조가 마크다운 단계에서 소실됨.

이는 시스템 불안정성이 아닌,
구조 분리 정확도의 통계적 한계에 해당한다.

---

## 3. Structural Limitation Analysis

### 3.1 좌표 정보 활용 범위의 제한

현재 시스템은 PDF의 bbox 좌표를 다음 용도로 사용한다:

- 텍스트 읽기 순서 재구성
- Y-tolerance 기반 행 병합
- 표 영역 감지 및 제거

그러나 마크다운 변환 이후에는
물리적 좌표 정보가 소실되며,
구조 분할은 오직 텍스트와 폰트 통계 정보에 의존한다.

결과적으로:
페이지 상단 중앙 배치, 여백, 물리적 위치 기반 판단은
의미론적 구조 판별에 활용되지 않는다.

---

### 3.2 Statistical Font Profiling – Narrow Gap Issue

헤더 검출은 폰트 크기 클러스터링에 기반한다.

#### 실패 조건
- 헤더와 본문의 폰트 차이 ≤ 1pt
- 폰트 분포가 단일 클러스터로 수렴

대표 사례: `sample28`

#### 현상
- 제목이 본문 그룹으로 분류됨
- Markdown 헤더 태그 미생성
- 대형 청크 생성 → 검색 노이즈 증가

#### 핵심 진단
이는 알고리즘 오류가 아니라,
물리적 속성만으로는 구분이 불가능한 영역
(Indistinguishable Region)에 해당한다.

---

## 4. Architectural Positioning (v2.1.3)

v2.1.3은 다음과 같은 특성을 갖는다:

- 결정론적(Deterministic)
- 동일 입력 → 동일 결과
- 데이터 무결성 최우선
- 의미론은 통계 기반 추론

현재 제약은 설계 실패가 아닌,
확장 예정 영역에 해당하는 관리 가능한 기술 부채(Managed Technical Debt)이다.

---

## 5. v3.0 Architectural Upgrade Roadmap

### Priority 1 — HWP Direct Parsing (Structural Resolution)

PDF 변환 이전 단계에서
HWP 원본의 논리 스타일(제목1, 개요1 등)을 직접 추출.

목표:
- 폰트 크기 의존도 제거
- Narrow Gap 문제 구조적 해결
- 구조 판별 정확도 근본적 향상

---

### Priority 2 — Hybrid Confidence Signaling (Operational Safeguard)

폰트 클러스터 간 간격이 임계치 이하일 경우:

- [Low Confidence] Warning 발생
- 로그 기반 수동 검수 대상 자동 선별
- 품질 모니터링 지표 도입

---

### Priority 3 — Selective LLM Structural Refinement (Cost-aware Fallback)

Low Confidence 문서에 한해:
- LLM 기반 제목 재구성 시도
- 제한적·선별적 투입
- 비용 통제 및 결정론 유지

---

## 6. Transition Strategy

v2.1.3은 안정적 대량 처리 시스템으로 유지하며,
v3.0은 다음 방향으로 진화한다:

Deterministic Indexing Engine  
→ Structure-aware Preprocessing Engine

즉,
"정확하게 저장하는 시스템"에서  
"구조를 이해하고 저장하는 시스템"으로의 전환이다.

---

## 7. Conclusion

Preprocessor Pipeline v2.1.3은
데이터 무결성과 실행 안정성 측면에서 완전한 성공을 달성하였다.

다만,
물리적 폰트 속성에 의존한 구조 판별은
미세한 폰트 차이가 존재하는 특수 문서에서 한계를 가진다.

해당 제약은 예외적 케이스에 국한되며,
차기 버전에서 HWP 직접 구조 추출을 통해
근본적 개선이 가능하다.

v2.1.3은 안정화 단계,
v3.0은 구조 지능화 단계로 정의된다.
