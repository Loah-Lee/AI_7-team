## P0-1: Dense Indexing Doc_ID 기반 Upsert

**파일**: `storage_step5.py`

**문제**: 기존 dense indexing은 테이블 존재 시 삽입을 건너뛰어 재처리 시 벡터가 갱신되지 않았음.

**수정 내용**:

| 항목 | 변경 |
|------|------|
| `upsert_dense_vectors()` 함수 신규 추가 | doc_id 기반 DELETE→INSERT 구현 |
| 삭제 로직 | `json_extract(metadata, '$.doc_id')` 기반 기존 벡터 제거 |
| 테이블 미존재 시 | `SQLiteVec.from_texts()`로 신규 생성 |
| `main()` 내 기존 dense 로직 | `upsert_dense_vectors()` 호출로 교체 |
| `main()` 내 `embeddings` 변수 | 제거 (각 함수가 독립적으로 로드) |

**핵심 보장**: Append 금지, 전체 Drop 금지, Doc-level Replace만 수행.

## P0-2: Preprocessor Dense Upsert 호출 및 검증

**파일**: `preprocessor.py`

**수정 내용**:

| 항목 | Before | After |
|------|--------|-------|
| import | `extract_hierarchy_data, load_chunks_from_disk` | `upsert_dense_vectors` |
| indexing 호출 | `initialize_sparse_db()` 단독 | `initialize_sparse_db()` + `upsert_dense_vectors()` |
| result dict 필드 | `embedding_count` | `sparse_count`, `dense_count` |
| 검증 로그 | chunk vs embedding 비교 | chunk == sparse == dense 3자 비교 |
| CSV fieldnames | `embedding_count` | `sparse_count`, `dense_count` |
| exception result dict | 동일 필드 반영 | `sparse_count: 0`, `dense_count: 0` |

**검증 기준**: `chunk_count == sparse_count == dense_count` 불일치 시 경고 출력.

## P0-3: Chunker Page Range 정밀화

**파일**: `chunker_step4.py`

**문제**: 모든 chunk가 소속 섹션 전체의 `page_start`/`page_end`를 그대로 복사.

**수정 내용**:

| 항목 | Before | After |
|------|--------|-------|
| `Section` dataclass | `content_lines: List[str]` | `line_pages: List[int]` 필드 추가 (parallel array) |
| `split_into_sections()` | page 마커에서 current_page만 추적 | 각 content line에 대응하는 page 번호를 `line_pages`에 저장 |
| `identify_blocks()` | `(block_type, lines)` 반환 | `(block_type, lines, pages)` 반환 |
| `create_chunks_from_section()` | `section.page_start/end` 직접 복사 | chunk에 실제 포함된 라인/블록의 page 번호만 수집하여 `min(pages)`/`max(pages)` 계산 |
| 중복 코드 | metadata dict 리터럴 11회 반복 | `_make_chunk()` 헬퍼로 통합 |
| overlap buffer | sentences만 추적 | `overlap_pages_buffer` 추가하여 overlap에서도 page 정보 유지 |

**결과**: chunk의 `page_start`/`page_end`가 해당 chunk에 실제로 포함된 텍스트의 페이지 범위만 반영.
