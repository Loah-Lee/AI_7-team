# v2.1.3 Strict Contract Enforcement 보고서

## 목적

`assign_uids()`(v2.1.2)가 Fail-Fast로 `doc_id`·`uid` 무결성을 보장하므로,
하류 함수 `initialize_sparse_db()`에 남아 있던 방어적 fallback 코드를 제거하여
Strict Contract 체계를 완성한다.

---

## 적용 내용

**파일**: `storage_step5.py`
**함수**: `initialize_sparse_db`

| 행 | Before (v2.1.2) | After (v2.1.3) |
|----|-----------------|-----------------|
| doc_ids 집합 생성 | `c.get('doc_id', 'unknown')` | `c['doc_id']` |
| uid 접근 | `chunk.get('uid', str(chunk['chunk_id']))` | `chunk['uid']` |
| doc_id 접근 | `chunk.get('doc_id', 'unknown')` | `chunk['doc_id']` |

**제거된 fallback 패턴**: 총 3건의 `.get(..., fallback)` → 직접 키 접근으로 교체.

**전제 조건**: `assign_uids()` 호출 이후에만 `initialize_sparse_db()`가 호출됨.
계약 위반 시 `assign_uids()`에서 `RuntimeError`로 즉시 종료되므로,
`initialize_sparse_db()`에 도달하는 chunk는 반드시 유효한 `doc_id`·`uid`를 보유.

## Contract 체계 완성 상태

| 계층 | 함수 | 역할 | 상태 |
|------|------|------|------|
| 계약 집행 | `assign_uids()` | doc_id 존재·유효성·unknown 금지·metadata 일관성 | v2.1.2 완료 |
| Sparse 인덱싱 | `initialize_sparse_db()` | Strict 직접 접근 (fallback 없음) | **v2.1.3 완료** |
| Dense 인덱싱 | `upsert_dense_vectors()` | doc_id 기반 DELETE→INSERT | v2.1.1 완료 |

전체 파이프라인에서 `'unknown'` fallback 경로가 완전히 제거됨.
