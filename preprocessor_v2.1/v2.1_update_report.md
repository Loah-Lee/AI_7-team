## 3. 단계별 변경 상세

### 3.1 Parser (parser_step1.py)

#### 페이지 마커 교체

| 항목 | v2.0 | v2.1 |
|------|------|------|
| 마커 형식 | `<!-- page: N -->` | `[[PAGE:N]]` |
| 삽입 위치 | 각 페이지 마크다운 첫 줄 | 동일 (각 물리 페이지의 최초 텍스트 블록 이전) |

이 변경으로 Auditor/Chunker가 동일한 `[[PAGE:N]]` 리터럴 토큰을 계약 기준점으로 사용할 수 있게 되었다.

#### H1/H2 계층 역전 방지

`_maybe_swap_h1_h2()` 함수 추가. 아래 3가지 조건을 **모두** 만족할 때만 H1↔H2 스왑:

| 조건 | 설명 |
|------|------|
| H1 빈도 ≤ 2 | H1 클러스터에 해당하는 span이 2개 이하 |
| H1 비율 < 10% | H1 / (H1 + H2) < 0.10 |
| H1 위치 ⊆ 페이지 0~1 | H1 span이 모두 물리적 표지/첫 페이지에만 존재 |

**적용 대상**: sample20처럼 표지 크기(47.7pt)가 H1에 잡히고 실제 본문 헤더(32pt)가 H2에만 할당되는 케이스.

### 3.2 Auditor (auditor_step2.py)

#### `[[PAGE:n]]` 마커 보존 (P0 계약)

`_process_body()`에서 `[[PAGE:n]]` 패턴을 regex split으로 분리한 뒤, 각 segment에만 텍스트 정제를 적용하고 마커를 원형 그대로 재결합한다.

#### 불릿 표준화

```
○ ● ■ ※ ◆ ◇ ▶ ▷ ► → *
```

`_BULLET_RE`로 행 시작의 불릿 기호를 `* `로 교체. Chunker의 불릿 블록 인식을 위한 정규화.

#### 테이블 셀 조건부 줄바꿈 병합

`merge_table_cell_linebreaks()`: 테이블 행(`|...|`) 바로 다음에 오는 non-table/non-header/non-marker 텍스트를 이전 테이블 행에 공백으로 병합. PDF 추출 시 셀 내 줄바꿈이 별도 행으로 분리되는 문제 해결.

#### 단일글자 교정 안전장치

`SPACING_SAFETY_RATIO = 0.15`: 교정 전후 텍스트 길이 변화가 15%를 초과하면 교정을 취소하고 원문을 반환. 과교정으로 인한 데이터 손상 방지.

---

### 3.3 Chunker (chunker_step4.py)

#### `[[PAGE:n]]` 마커 소비

| 항목 | v2.0 | v2.1 |
|------|------|------|
| 마커 regex | `r'<!--\s*page:\s*(\d+)\s*-->'` | `r'\[\[PAGE:(\d+)\]\]'` |
| 처리 | 페이지 상태 갱신 후 content에서 제거 | 동일 |

#### 불릿 블록 원자성

`_classify_line()`으로 각 행을 `table` / `bullet` / `text` 3종으로 분류.

불릿 블록(`* ` 시작 연속 행)은 아래 조건에서만 문장 분할 허용:

| 조건 | 임계값 |
|------|--------|
| 블록 크기 | > `CHUNK_SIZE × 0.8` (1,200자) |
| 내부 문장 수 | ≥ `BULLET_MIN_SENTENCES` (3개) |

두 조건 중 하나라도 만족하면 분할, 아니면 원자적으로 유지.

#### 작은 청크 병합 시 섹션 경로 일치 조건

`_merge_small_chunks()`에 `_same_section_path()` 조건 추가. `section_level1`과 `section_level2`가 **모두 동일**한 경우에만 MIN_CHUNK_SIZE 미만 청크를 이전 청크에 병합. 서로 다른 섹션의 내용이 합쳐지는 것을 방지.

### 3.4 Storage (storage_step5.py)

#### SHA-256 기반 결정론적 doc_id

```python
compute_doc_id(parser_raw_path) → SHA-256(파일 bytes)[:16]
```

- 해시 대상: **Parser raw output** (Auditor 이전 `step1_parsed_*.md`)
- Parser 로직 변경 시 해시 자동 변경 → 재인덱싱 트리거
- 동일 로직/환경에서는 해시 안정성 보장

#### doc_id 단위 DELETE→INSERT upsert

`initialize_sparse_db()`에서 기존 rowid 기반 스킵 → doc_id 기반 전면 교체:

1. 대상 doc_id의 기존 row 전부 DELETE
2. 새 chunk 전부 INSERT (단일 트랜잭션)

#### UID 안정성 정책

```
UID = f"{doc_id}_{local_chunk_index}"
```

- `local_chunk_index`: 해당 문서 내 0-based 순서
- Chunker 로직 변경 시 index 변동 가능 → 전면 교체 전략상 정상 동작

#### Sparse 테이블 스키마 변경

| 컬럼 | v2.0 | v2.1 |
|------|------|------|
| uid | 없음 | 추가 |
| doc_id | 없음 | 추가 (UNINDEXED) |
| nouns | 있음 | 유지 |
| text | 있음 (UNINDEXED) | 유지 |

### 3.5 Preprocessor (preprocessor.py)

#### 파일 단위 try-except 격리

`process_single_pdf()` 호출을 try-except로 감싸 개별 파일 오류가 전체 프로세스를 중단시키지 않음. 실패 시 error 메시지를 기록하고 다음 파일로 계속 진행.

#### 즉시 실패 처리

생성된 chunk 수가 0이면 해당 파일을 즉시 `status='failed'`로 처리하고 summary에 기록.

#### 이상 탐지 (동적/정적 병행)

| 구간 | 조건 | 임계값 |
|------|------|--------|
| 초기 (N < 10) | 절대 시간 | 60초 |
| 통계 (N ≥ 10) | 평균 대비 | 3배 초과 |

`check_time_anomaly()` 함수로 구현. 임계값 초과 시 경고 로그 출력 (프로세스 중단은 하지 않음).

#### 데이터 불일치 경고

`chunk_count`와 `embedding_count` 불일치 시 경고 로그 출력.

#### execution_summary.csv

| 컬럼 | 설명 |
|------|------|
| file | PDF 파일명 |
| status | success / failed |
| duration_sec | 처리 시간 (초) |
| chunk_count | 생성된 청크 수 |
| embedding_count | 삽입된 임베딩 수 |
| reindexed | 재인덱싱 여부 |
| error | 에러 메시지 (실패 시) |

## 6. 미수행 사항

- **99개 전체 실행**: v2.1 코드로 99개 PDF 전체 파이프라인 실행은 별도 수행 필요 (`preprocessor.py` 실행)
- **Dense indexing의 doc_id 단위 upsert**: Sparse 테이블은 doc_id 단위 DELETE→INSERT로 교체 완료. Dense 테이블(SQLiteVec)은 LangChain API 제약으로 테이블 존재 시 스킵하는 기존 방식 유지. 전체 재인덱싱이 필요하면 `DB/document.db` 삭제 후 재실행.
- **Hierarchy 테이블 doc_id upsert**: Dense와 동일한 제약. 전체 재생성 방식 유지.
