# [v2.2] Document Anchor + Hierarchy Scope 확장 설계 명세 (JOIN 기반 정합 수정)

본 설계는 v2.1.3 DB를 확장하여 hierarchy를 물리적으로 생성하고,
Document Anchor 및 Hierarchy Scope를 Query 레벨에서 지원하는 구조로 진화시킨다.
Sparse 검색은 FTS5 단독 필터가 아니라 chunks 테이블과 JOIN하여 metadata 기반 필터를 적용한다.

---

## 1. 설계 원칙

1. Single Source of Truth는 항상 `chunks`
2. 모든 Scope 필터는 `chunks.metadata` 기준으로 정의
3. Sparse 검색은 반드시 `sparse → chunks JOIN` 후 필터 적용
4. DB 구조는 Dense/Sparse/RRF 전략과 독립

---

## 2. 물리 테이블 구성

### 2.1 chunks (검색 본체)

rowid
text
metadata (JSON)
text_embedding

### metadata 확장 규격

    {
      "type": "chunk",
      "doc_id": "eb69a3dfeb69208c",
      "document_title": "제안요청서",
      "uid": "eb69a3dfeb69208c_0",
      "chunk_order": 0,
      "section_uid": "eb69a3dfeb69208c_h_1",
      "page_start": 1,
      "page_end": 3
    }

#### 생성 계약

- chunk_order는 doc_id 단위 0-based sequential
- 동일 doc_id 내 유일
- deterministic 재현 보장
- document_title은 lower + trim 정규화

---

### 2.2 hierarchy (범위 메타 인덱스)

rowid
text
metadata
text_embedding

metadata:

    {
      "type": "hierarchy",
      "doc_id": "...",
      "document_title": "...",
      "uid": "..._h_1",
      "level": 1,
      "title": "...",
      "parent_uid": null,
      "start_order": 0,
      "end_order": 15
    }

역할:

- Section Scope의 chunk_order 범위 정의
- 검색 대상이 아니라 범위 가이드

---

### 2.3 sparse (FTS5)

uid
doc_id UNINDEXED
nouns
text UNINDEXED

중요:

- 실제 Scope 필터는 JOIN 후 chunks.metadata 기준으로 수행

---

## 3. Scope 정의 (모든 필터는 chunks 기준)

### 3.1 Anchor Scope

    json_extract(chunks.metadata, '$.document_title') IN (...)

### 3.2 Hierarchy Scope

    json_extract(chunks.metadata, '$.chunk_order')
    BETWEEN start_order AND end_order

반드시 동일 문서 조건과 결합.

---

## 4. 검색 시 JOIN 구조

### 4.1 Dense Filtered

    SELECT c.*
    FROM chunks c
    JOIN chunks_vec v ON c.rowid = v.rowid
    WHERE v.text_embedding MATCH ?
      AND json_extract(c.metadata, '$.document_title') IN (...)
    ORDER BY v.distance
    LIMIT k;

---

### 4.2 Sparse Filtered (JOIN 기반)

    SELECT c.rowid, c.text, c.metadata
    FROM sparse s
    JOIN chunks c
      ON s.uid = json_extract(c.metadata, '$.uid')
    WHERE s.nouns MATCH ?
      AND json_extract(c.metadata, '$.document_title') IN (...)
    ORDER BY bm25(s)
    LIMIT k;

Hierarchy Scope가 있을 경우:

    AND json_extract(c.metadata, '$.chunk_order')
        BETWEEN start_order AND end_order

추가 결합.

---

## 5. 인덱스 설계

### Document Anchor

    CREATE INDEX idx_chunks_doc_title
    ON chunks(json_extract(metadata, '$.document_title'));

### Section Scope

    CREATE INDEX idx_chunks_order
    ON chunks(json_extract(metadata, '$.chunk_order'));

### 복합 인덱스

    CREATE INDEX idx_chunks_doc_order
    ON chunks(
      json_extract(metadata, '$.document_title'),
      json_extract(metadata, '$.chunk_order')
    );

---

## 6. 데이터 무결성 계약

1. sparse.uid == metadata.uid 반드시 일치
2. Dense 행 수 == Sparse 행 수
3. doc_id 단위 DELETE→INSERT
4. chunk_order 결정론적 재현
5. hierarchy.start_order/end_order는 실제 chunk_order 범위와 완전 일치
