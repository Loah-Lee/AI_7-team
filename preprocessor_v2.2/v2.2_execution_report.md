## 1. v2.1.3 → v2.2 변경 사항

### 신규 기능

| 항목 | 설명 |
|------|------|
| `hierarchy` 테이블 | L1/L2 섹션 범위 메타 인덱스 물리적 생성 |
| `metadata.type` | `"chunk"` 고정값 (hierarchy와 구분) |
| `metadata.chunk_order` | doc_id 단위 0-based 순서 번호 |
| `metadata.section_uid` | 소속 hierarchy 엔트리 UID (L2 우선, L1 fallback) |
| `document_title` 정규화 | lower + trim 적용 |
| JSON 인덱스 3종 | `idx_chunks_doc_title`, `idx_chunks_order`, `idx_chunks_doc_order` |
| 무결성 검증 함수 | `verify_integrity()` — 5단계 자동 검증 |

### 변경 없음

| 항목 | 값 |
|------|-----|
| 임베딩 모델 | `jhgan/ko-sroberta-multitask` (768d) |
| FTS5 토크나이저 | kiwipiepy 명사 추출 |
| Upsert 패턴 | doc_id 기반 DELETE→INSERT |
| UID 형식 | `{doc_id}_{chunk_index}` |
| Fail-Fast 계약 | `assign_uids()` RuntimeError |

## 3. v2.2 metadata 구조

```json
{
  "document_title": "제안요청서",
  "source_file": "sample1.pdf",
  "section_level1": "Ⅳ",
  "section_level2": "제안요청내용",
  "page_start": 5,
  "page_end": 7,
  "chunk_size": 1423,
  "created_at": "2026-02-13T01:09:08.595978",
  "uid": "eb69a3dfeb69208c_27",
  "doc_id": "eb69a3dfeb69208c",
  "type": "chunk",
  "chunk_order": 27,
  "section_uid": "eb69a3dfeb69208c_h_7"
}
```

신규 필드:
- `type`: 항상 `"chunk"` (hierarchy 엔트리는 `"hierarchy"`)
- `chunk_order`: doc_id 단위 0-based 순서 (결정론적)
- `section_uid`: 소속 hierarchy 엔트리의 uid (없으면 `null`)

## 5. 인덱스 목록

`storage_step5.py`의 `ensure_indexes()`가 5종 인덱스를 자동 생성한다.

| 인덱스 | 대상 | 용도 |
|--------|------|------|
| `idx_chunks_doc_title` | `json_extract(metadata, '$.document_title')` | Document Anchor 필터 가속 |
| `idx_chunks_order` | `json_extract(metadata, '$.chunk_order')` | Hierarchy Scope 범위 검색 가속 |
| `idx_chunks_doc_order` | `(document_title, chunk_order)` | Anchor + Scope 복합 필터 가속 |
| `idx_chunks_uid` | `json_extract(metadata, '$.uid')` | Sparse→Chunks 2단계 쿼리 Step2 가속 |
| `idx_chunks_doc_id` | `json_extract(metadata, '$.doc_id')` | doc_id 기반 조회/upsert 가속 |
