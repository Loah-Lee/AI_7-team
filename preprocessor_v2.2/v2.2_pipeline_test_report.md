### 5.2 section_uid 미연결 chunk (11.9%)

전체 8,185 chunk 중 970개(11.9%)가 `section_uid = null`이다.
이는 `section_level1 = "N/A"`인 chunk (표지, 목차 등 섹션 바깥 텍스트)에 해당하며, 정상 동작이다.

### 5.3 인덱스 목록

| 인덱스 | 대상 |
|--------|------|
| `idx_chunks_doc_title` | `json_extract(metadata, '$.document_title')` |
| `idx_chunks_order` | `json_extract(metadata, '$.chunk_order')` |
| `idx_chunks_doc_order` | `(document_title, chunk_order)` 복합 |
| `idx_chunks_uid` | `json_extract(metadata, '$.uid')` |
| `idx_chunks_doc_id` | `json_extract(metadata, '$.doc_id')` |

> `idx_chunks_uid`와 `idx_chunks_doc_id`는 테스트 과정에서 Sparse→Chunks JOIN 성능 문제로 추가된 인덱스이다. v2.2 설계 명세의 3종에 2종이 추가되어 총 5종.

## 6. 성능 참고

### FTS5 + Chunks JOIN 성능 이슈

단일 SQL로 `sparse JOIN chunks` 쿼리를 실행하면 uid 매칭에 시간이 걸린다.
**2-step 쿼리 패턴**(FTS5로 uid 후보 추출 → uid로 chunks 개별 조회)이 안정적이다.

| 쿼리 패턴 | 소요 시간 |
|-----------|----------|
| FTS5 단독 (doc_id 필터) | ~1.5s |
| uid → chunks 개별 조회 (30건) | ~0.06s |
| 단일 JOIN (sparse + chunks) | 타임아웃 위험 |

**권장**: 2-step 방식 또는 충분한 인덱스 확보 후 JOIN 사용.
